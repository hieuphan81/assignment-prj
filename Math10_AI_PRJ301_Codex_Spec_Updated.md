# PRJ301 -- Math10 AI Project Specification & Development Plan

## 1. Project Overview

Project name: Math10 AI

Goal: Build a web-based Grade 10 Mathematics learning platform for
Vietnamese students.

Main idea: - Students learn Grade 10 Mathematics through lessons
containing text, YouTube videos, and external resources. - Students
practice multiple-choice and essay questions. - Teachers manage lessons,
topics, students, and question banks. - AI can generate questions for
teachers. - AI acts as a step-by-step tutor for students instead of
immediately revealing the final answer. - Students can upload an image
of an essay solution and receive AI feedback.

Reference platform: - Primary reference: OLM - Secondary UX/learning
references: Khan Academy, Quizlet, Duolingo, VioExam, PhET - Do NOT copy
their UI. Use them only as functional/UX references.

Target scope: - Grade 10 Mathematics only. - Three roles: ADMIN,
TEACHER, STUDENT.

# 6. Database Design

## USERS

Fields: - user_id PK - username - password_hash - full_name - email -
role - teacher_id nullable FK -> USERS (used only for STUDENT assignment)
- status - created_at

Roles: - ADMIN - TEACHER - STUDENT

## SUBJECTS

Fields: - subject_id PK - subject_name - description - created_by FK -\>
USERS - status - created_at

For current scope, create one subject: - Mathematics Grade 10

## Topics / Chapters

For the compact six-table MVP, store `topic_name`, `topic_description`,
and `topic_order` on LESSONS. This works for one subject when each lesson
belongs to one topic. If topics must be shared across subjects or lessons,
normalize them into a TOPICS table; that raises the table count to seven
and should be explained against the rubric.

## LESSONS

Teacher access rule: teachers manage lessons they created; admins manage
all lessons; students can access published lessons. Enforce ownership and
role checks on the server.

Fields: - lesson_id PK - subject_id FK -> SUBJECTS - teacher_id FK ->
USERS - topic_name - topic_description - topic_order - title -
description - content - video_url - resource_url - order_index - status
- created_at

## QUESTIONS

Fields: - question_id PK - lesson_id FK -\> LESSONS - created_by FK -\>
USERS - question_type - question_text - option_a - option_b - option_c -
option_d - correct_answer - explanation - difficulty - status -
created_at

question_type: - MCQ - ESSAY

difficulty: - EASY - MEDIUM - HARD

For ESSAY questions, options can be NULL.

## ATTEMPTS

Teacher-to-student scope: In the six-table MVP, add nullable `teacher_id`
to USERS for student accounts, referencing the responsible teacher.
Admins assign students. Teachers can view/manage only their assigned
students, attempts, and progress; admins can view all. Enforce these
checks on the server. If students need multiple teachers, use a
TEACHER_STUDENT junction table and update the table-count explanation.

Fields: - attempt_id PK - question_id FK -\> QUESTIONS - student_id FK
-\> USERS - answer_text - image_path / image_reference - is_correct -
score - feedback - submitted_at

## AI_INTERACTIONS

Fields: - interaction_id PK - attempt_id FK -\> ATTEMPTS -
student_input - ai_response - step_number - is_final - created_at

Purpose: Store the step-by-step AI tutoring conversation for an attempt.

# 8. Core Business Flows

## Student Learning Flow

Login -\> Student Dashboard -\> Select Subject -\> Select Topic/Lesson
-\> Read/watch lesson -\> Start Practice -\> Answer question -\> Submit
-\> Save attempt -\> Show result

## MCQ AI Flow

Student submits answer -\> System checks answer -\> If correct: show
success go to next question -\> If wrong: send question + student
answer + current context to AI AI identifies error AI gives ONE hint
student enters response AI evaluates response if correct -\> continue if
wrong -\> provide next hint repeat until solved or hint limit reached
save all AI interactions

IMPORTANT: AI should NOT immediately reveal the final answer after the
first mistake.

## Essay AI Flow

Student opens essay question -\> Student writes solution -\> Student
uploads image -\> Validate image -\> Send image/question/context to AI
vision-capable API -\> AI extracts/understands the solution -\> AI
identifies incorrect step(s) -\> AI provides feedback/hint -\> Save
attempt and AI interaction -\> Student can retry

### Essay Image Upload Requirements

- Accept JPEG/JPG, PNG, and WEBP only; validate extension and actual
  content/MIME on the server.
- MVP limit: one image per answer, maximum 10 MB. Reject empty,
  oversized, unreadable, or unsupported files with a clear message.
- Generate a random server-side filename; never use the submitted
  filename as a path. Store outside the public web root or in private
  object storage.
- Save only a relative storage key/path in `ATTEMPTS.image_path`.
  Authorize image reads for the owning student, assigned teacher, or
  admin. Remove rejected temporary files and do not log image contents.

## Teacher Question Flow

Teacher creates question OR Teacher requests AI question generation -\>
AI generates draft questions -\> Teacher reviews -\> Teacher edits if
needed -\> Teacher saves/publishes

## Admin Flow

Admin login -\> Dashboard -\> Manage users -\> Manage teachers -\>
Manage students -\> Manage subjects/topics -\> Manage lessons/questions
-\> Configure AI

### AI Configuration Details

The admin page should support selecting the provider and model, setting
or replacing the API credential, configuring the tutor hint limit, and
enabling/disabling question generation, tutoring, and image feedback.
Keep credentials in environment variables or protected server-side
secret storage. Never put keys in source code, browser code, logs, or API
responses. Show only configured status and a masked value. Provide a
server-side connection check with a safe status message, without exposing
raw provider errors.

# 9. AI Tutor Prompt Requirements

The AI Tutor should support Grade 10 and general high-school mathematics,
including problems outside the local bank, to the extent the configured
provider can solve them reliably. Do not promise correct answers for
every possible problem. For ambiguous, unreadable, out-of-scope, or
uncertain problems, ask for clarification or state that reliable guidance
is unavailable. Handle timeouts, rate limits, and provider errors without
exposing raw internal errors.

The AI Tutor should be configured approximately with these rules:

SYSTEM ROLE: You are Math10 AI Tutor for Vietnamese Grade 10
Mathematics.

RULES: 1. Guide the student instead of immediately giving the final
answer. 2. Analyze the student's current answer. 3. Identify the first
important incorrect step. 4. Give only one useful hint at a time. 5. Ask
the student to calculate, enter a value, or explain the next step. 6.
Wait for the student's new input before continuing. 7. If the student is
correct, confirm it and move to the next step. 8. If the student is
wrong again, provide a stronger hint. 9. Adapt explanations to Grade 10
Mathematics knowledge. 10. Do not invent formulas or facts. 11. Keep the
conversation focused on the current problem. 12. Reveal the full
solution only when the configured hint limit is reached or the system
explicitly requests the final solution. 13. Return structured
information that the backend can process.

The implementation should pass: - question - topic - difficulty -
correct answer/solution if available - student's current answer -
previous AI interactions - current step number

to the AI service.

# 12. Grade 10 Mathematics Content

The project selects **Toán 10 – Kết nối tri thức với cuộc sống**, Tập 1
and Tập 2. Keep topic/lesson ordering consistent with its nine chapters:

1. Mệnh đề và tập hợp
2. Bất phương trình và hệ bất phương trình bậc nhất hai ẩn
3. Hệ thức lượng trong tam giác
4. Vectơ
5. Các số đặc trưng của mẫu số liệu không ghép nhóm
6. Hàm số, đồ thị và ứng dụng
7. Phương pháp tọa độ trong mặt phẳng
8. Đại số tổ hợp
9. Tính xác suất theo định nghĩa cổ điển

The database seed includes the 27 lesson titles in these chapters. The
lesson explanations and questions must be original project content and
reviewed by a teacher before publication.

Initial sample data: - 6--8 topics - 2--3 lessons per topic - 5--10
questions per lesson - Include both MCQ and ESSAY - Include
EASY/MEDIUM/HARD

# 19. Codex Working Rules

When implementing the project:

1.  Work incrementally.
2.  Do not rewrite working modules unnecessarily.
3.  Follow MVC architecture.
4.  Keep Controller, Service, DAO, and Model responsibilities separated.
5.  Use reusable methods/components.
6.  Use parameterized SQL queries.
7.  Add server-side validation.
8.  Add clear error handling.
9.  Keep AI provider code inside a dedicated AI service.
10. Never hard-code API keys.
11. Keep AI prompt templates configurable.
12. Do not let AI-generated questions bypass teacher review.
13. Store AI conversation steps in AI_INTERACTIONS.
14. Do not expose internal API errors directly to students.
15. Use sample data for development.
16. Keep the project buildable after every phase.
17. After each major feature, run/build/test the application.
18. Do not start the next major phase if the current phase is broken.
19. Prefer simple implementations that are reliable and easy to explain
    during Q&A.
20. Do not add unnecessary frameworks or dependencies.
